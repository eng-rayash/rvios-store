# دليل نشر RVIOS Store

> منصّة تحمل متاجر تجّار حقيقيين وطلباتهم. كل خطوة هنا مكتوبة
> لأن تركها يُنتج عطلاً يدفع ثمنه تاجر لا مطوّر.

---

## ما تحتاجه قبل البدء

| المتطلّب | لماذا |
|---|---|
| **Node 24+** | المشروع يستعمل `--env-file` و`fetch` المدمج |
| **PostgreSQL 16+** | القاعدة — خارجية دائماً، لا داخل الحاوية |
| **نطاق** | رابط المتجر يُنشر في واتساب مرة واحدة ولا يُصحَّح |
| **حساب Meta للأعمال** | لإرسال رموز التحقق (اختياري في البداية) |

الاعتماديات: الحزمة واحدة تضمّ الواجهة (Next وReact) والخادم معاً.
لكنّ **الخادم نفسه** ما يزال على اعتمادية واحدة (`postgres`): هو ما
يحمل المصادقة والطلبات والفوترة، وكل حزمة تدخله تدخل معها سطح هجوم.
تحقّق بنفسك: `npm run check:server-deps` — يقرأ ما يستورده `server/`
فعلاً، لا ما هو مثبَّت في الشجرة.

## ١. الأسرار — قبل كل شيء

```bash
cp .env.example .env
npm run secrets
```

الأمر يولّد أربعة أسرار قويّة. انسخها إلى `.env`.

**الإقلاع في الإنتاج يتوقّف** إن كان أيٌّ منها ناقصاً أو ضعيفاً —
هذا مقصود. الفحص يرفض:

- `RVIOS_ADMIN_PASS` أقصر من ١٦ محرفاً أو يبدأ بـ`admin`/`password`/`rvios`…
- `OTP_PEPPER` أقصر من ٣٢ محرفاً
- `VISIT_SALT` أقصر من ١٦ محرفاً
- `DATABASE_URL` غائباً

> **لا تُعِد توليد `OTP_PEPPER` على قاعدة عاملة.** كل رمز تحقّق
> أُرسل ولم يُستعمل بعد سيفشل. المستخدمون الذين ينتظرون رمزاً
> في تلك اللحظة لن يدخلوا.

## ٢. النشر على منصّة مُدارة (Render)

المسار الموصى به: بلا خادم تديره ولا nginx ولا شهادة تجدّدها.

### أ. ادفع المستودع إلى GitHub

```bash
git remote add origin git@github.com:<حسابك>/rvios-store.git
git push -u origin main
```

### ب. أنشئ من المخطّط

في Render: **New → Blueprint** واختر المستودع. يقرأ `render.yaml`
فيُنشئ ثلاثة أشياء معاً:

1. خدمة ويب من `Dockerfile`
2. قاعدة PostgreSQL — ويحقن `DATABASE_URL` تلقائياً
3. **قرصاً دائماً** على `/data`

> **القرص ليس اختيارياً مع التخزين المحلي.** القاعدة خارجية،
> لكن صور المتاجر ملفات على القرص. بلا هذا القرص تُمحى كل صورة
> رفعها تاجر مع أول إعادة نشر — والصور لا تُستعاد من نسخة
> القاعدة. البديل: `STORAGE_DRIVER=r2` (القسم ٥.٥) فيصير
> التطبيق بلا حالة ويُستغنى عن القرص كلياً.

### ج. املأ الأسرار

في **Environment** ضع القيم المعلّمة `sync: false`:

```
RVIOS_ADMIN_PASS   OTP_PEPPER   VISIT_SALT   PUBLIC_URL
```

`PUBLIC_URL` هو عنوانك الكامل مع `https://` وبلا شرطة مائلة
أخيرة. بدونه تُبنى روابط المشاركة من ترويسات الطلب، وقد تخرج
خاطئة خلف وكيل.

### د. أول إقلاع

المخطّط يُطبَّق تلقائياً عند الإقلاع (`migrate()` قبل الاستماع).
تحقّق:

```bash
curl https://<نطاقك>/health
# {"ok":true,"stores":0,...}
```

## ٣. النشر على خادمك (بديل)

### Docker Compose

```bash
cp .env.example .env && npm run secrets     # املأ الأسرار
docker compose up -d
docker compose logs -f app
```

يرفع Postgres والتطبيق معاً. التطبيق ينتظر جاهزية القاعدة
(`service_healthy`) فلا يُقلع على قاعدة لم تقبل الاتصال بعد.

للإنتاج: احذف خدمة `db` ومنفذها، ومرّر `DATABASE_URL` خارجياً.

### systemd

```bash
sudo useradd -r -s /bin/false rvios
sudo mkdir -p /srv/rvios && sudo chown rvios:rvios /srv/rvios
# انسخ المصدر إلى /srv/rvios ثم:
# ‏--omit=dev لا يصلح هنا: بناء Next يحتاج tailwind وtypescript،
# وقراءة next.config.ts وقت التشغيل تحتاج typescript أيضاً.
cd /srv/rvios && npm ci && npm run build
sudo cp ops/rvios.service /etc/systemd/system/
sudo systemctl enable --now rvios
```

الوحدة مشدّدة أمنياً: `ProtectSystem=strict` و`NoNewPrivileges`
و`ReadWritePaths=/srv/rvios/data` وحدها.

**الوكيل العكسي والشهادة:**

```bash
sudo cp ops/nginx.conf /etc/nginx/sites-available/rvios
sudo ln -s /etc/nginx/sites-available/rvios /etc/nginx/sites-enabled/
sudo certbot --nginx -d rviosstore.com -d www.rviosstore.com
sudo nginx -t && sudo systemctl reload nginx
```

## ٤. واتساب — رموز التحقّق

بلا هذا يبقى `OTP_PROVIDER=console`: الرمز يُطبع في السجل ولا
يصل التاجر. صالح للتجربة، لا للإنتاج.

اتبع `SETUP-META.md` و`SETUP-OTP.md`، ثم:

```
OTP_PROVIDER=whatsapp,sms      # سلسلة: يجرّب الثاني إن فشل الأول
META_TOKEN=...
WA_PHONE_ID=...
WA_VERIFY_TOKEN=...            # نفسه يُدخَل في لوحة Meta
META_APP_SECRET=...            # لتوقيع webhook
```

**عنوان الـ webhook:** `https://<نطاقك>/api/webhook/whatsapp`

تحقّق من القناة قبل أن تعتمد عليها:

```bash
npm run check:wa
```

## ٥. أول تشغيل

### أنشئ حساب الإدارة

لا توجد شاشة تسجيل للإدارة. ادخل على `/admin` بـ
`RVIOS_ADMIN_PASS` الذي ولّدته.

> **حدّ معروف:** الإدارة كلمة مرور واحدة مشتركة لا حسابات
> منفصلة. سجل التدقيق (`audit_log`) يسجّل الأفعال لكنه لا
> يميّز فاعليها. لا تشارك هذه الكلمة مع أكثر من شخص.

### اضبط الأسعار

`/admin` ← الأسعار. الباقات تظهر للتجار بـ«—» حتى تضبطها،
ولا تُخترع أرقام.

### بيانات تجريبية (غير الإنتاج فقط)

```bash
npm run reset      # يمسح كل شيء ويبني أربعة متاجر
```

## ٥.٥ تخزين الصور — القرص أو Cloudflare R2

صور المتاجر ملفات، لا صفوف في القاعدة. أين تعيش قرارٌ له أثر
مباشر على النشر:

| | `local` | `r2` |
|---|---|---|
| يحتاج قرصاً دائماً | نعم | لا |
| ينجو من إعادة النشر | بالقرص فقط | دائماً |
| نسخ أكثر من واحدة للتطبيق | لا (القرص يمنع) | نعم |
| كلفة الخروج | من خادمك | مجانية على R2 |

الافتراضي `local` — يعمل بلا أي إعداد، ويكفي متجراً واحداً أو
عشرة. انتقل إلى R2 حين يصير التوسّع أو صفر-توقّف مطلوباً.

### التحويل إلى R2

١. من لوحة Cloudflare › **R2** › أنشئ سلة (مثلاً `rvios-media`).

٢. **R2** › *Manage API Tokens* › رمز بصلاحية **Object Read & Write**
   على هذه السلة وحدها. تظهر لك قيمتان مرّة واحدة فقط:
   `Access Key ID` و`Secret Access Key`.

٣. (اختياري ومستحسن) من إعدادات السلة › *Public Access* › فعّل
   نطاق `r2.dev`، أو اربط نطاقاً مخصّصاً مثل `cdn.example.com`.
   بدونه تبقى السلة خاصة ويمرّ خادمك بكل صورة — يعمل، لكنه
   أبطأ ويستهلك عرض نطاق خادمك.

٤. املأ المتغيّرات (في `.env` محلياً، أو لوحة المنصة إنتاجاً):

```
STORAGE_DRIVER=r2
R2_ACCOUNT_ID=…
R2_ACCESS_KEY_ID=…
R2_SECRET_ACCESS_KEY=…
R2_BUCKET=rvios-media
R2_PUBLIC_URL=https://cdn.example.com
```

٥. تحقّق قبل أن يرفع تاجر شيئاً:

```bash
npm run check:storage
```

يرفع ملفاً ويقرأه ويحذفه، ويجرّب النطاق العام. لا يطبع أي
مفتاح — الأطوال فقط، فيتمايز الناقص عن الخاطئ.

٦. على Render: احذف كتلة `disk` من `render.yaml`. التطبيق صار
   بلا حالة، فيمكن تشغيل أكثر من نسخة.

**الصور القديمة تبقى تعمل.** القيم المخزّنة على شكل
`/uploads/…` تُخدَم من القرص كما كانت، والجديد يذهب إلى R2.
لا ترحيل إجباري، ولا لحظة تنقطع فيها الصور.

**إيصالات التحويل لا تذهب إلى النطاق العام** حتى لو ضبطته.
هي تحمل أسماء وأرقام حسابات ومبالغ، فتبقى خلف الخادم كما هي
اليوم. الشعارات وصور المنتجات وحدها تُخدَم من Cloudflare.

## ٦. النسخ الاحتياطي

```bash
npm run backup            # نسخة الآن
npm run backup:list       # المتاح
npm run restore -- --latest
```

يتطلّب `pg_dump` و`psql` على المضيف (موجودان في صورة Docker).
إن غابا تُنسخ **الصور وحدها** ويُسجَّل التخطّي صراحةً — لا
تُعرض نسخة نصفية على أنها كاملة.

على منصّة مُدارة: المزوّد يوفّر استعادة زمنية للقاعدة، ونسخنا
تغطّي الصور.

**جرّب الاستعادة مرة واحدة على الأقل قبل أن تحتاجها.** نسخة لم
تُستعد قط ليست نسخة احتياطية — هي رجاء.

## ٧. قبل أن تفتح للتجار

```bash
npm run readiness     # تدقيق ذاتي: أمان · منتج · ما لم يُبنَ
npm test              # ٣٥٩ تأكيداً في إحدى عشرة حزمة
```

قائمة يدوية:

- [ ] `/health` يردّ `ok:true` من الإنترنت لا من الخادم فقط
- [ ] HTTPS يعمل و`http://` يحوّل إليه
- [ ] `PUBLIC_URL` مضبوط، وروابط المشاركة تظهر صحيحة في واتساب
- [ ] رمز تحقّق حقيقي وصل إلى هاتف حقيقي
- [ ] نسخة احتياطية أُنشئت **واستُعيدت** بنجاح
- [ ] `/admin` لا يقبل كلمة المرور الافتراضية
- [ ] أسعار الباقات مضبوطة
- [ ] رفعتَ صورة منتج وظهرت بعد إعادة نشر (يثبت ثبات التخزين)
- [ ] مع R2: `npm run check:storage` يمرّ بالرحلة الكاملة

## ٨. عزل المتاجر — طبقة ثانية

العزل مفروض في التطبيق: لا يمكن لمس جدول تابع إلا عبر
`scope(storeId)`، والـ SQL الحرّ يُرفض إن لم يذكر `store_id`.

بعد الانتقال إلى Postgres صار بالإمكان إسناده بضمانة من محرّك
القاعدة نفسه:

```bash
psql "$DATABASE_URL" -f ops/postgres-rls.sql
```

يُفعّل Row Level Security على الجداول العشرة التابعة. اقرأ
الملف أولاً — يتطلّب أن يتصل التطبيق بدور غير مالك الجداول،
وإلا تجاوز السياسة وبطل الغرض.

## ٩. حين يقع عطل

| العَرَض | الفحص |
|---|---|
| الإقلاع يتوقّف فوراً | السجل يذكر المتغيّر الناقص بالاسم — اقرأ أول سطر خطأ |
| `تعذّر الاتصال بقاعدة البيانات` | `DATABASE_URL` — جرّب `psql "$DATABASE_URL" -c 'select 1'` |
| صور المتاجر اختفت بعد نشر | القرص الدائم غير مركَّب على `/data`، أو `DATA_DIR` لا يشير إليه |
| رموز التحقّق لا تصل | `npm run check:wa` · راجع `wa_messages` — القبول ليس وصولاً |
| روابط المشاركة خاطئة | `PUBLIC_URL` غير مضبوط أو يحمل شرطة أخيرة |
| بطء مفاجئ | `/health` يعطي `uptime`؛ راجع سجلات المزوّد وعدد اتصالات القاعدة |

كل سطر سجل يحمل `req` — معرّف الطلب. يظهر أيضاً في ترويسة
`x-request-id`، فحين يشكو تاجر اطلب منه المعرّف وستجد طلبه فوراً.

## ملحق: متغيّرات البيئة

`.env.example` يوثّق **٤٨ متغيّراً** — كل ما يقرؤه `server/config.js`
بلا استثناء. الإلزامية في الإنتاج أربعة فقط:

```
DATABASE_URL   RVIOS_ADMIN_PASS   OTP_PEPPER   VISIT_SALT
```

وما عداها له قيمة افتراضية معقولة.
