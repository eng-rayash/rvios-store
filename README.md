# RVIOS Store

منصة متاجر إلكترونية متعددة المستأجرين للسوق اليمني.
كل تاجر يحصل على مساحة معزولة ورابط خاص `rviosstore.com/اسم-متجره`،
ومن يفتح الرابط يرى **متجر ذلك التاجر وحده**.

هذا التنفيذ الكامل للوثيقة في [`rvios-store-full-document.md`](rvios-store-full-document.md).
كل قسم في الكود يشير إلى بند الوثيقة الذي ينفّذه (`§٤.١`، `§٥.١` …).

---

## التشغيل

حزمة واحدة فقط (`postgres`) بلا اعتماديات متعدّية — شجرة تُدقَّق بنظرة.
المشروع يعمل على Node.js 22.5 أو أحدث، والقاعدة PostgreSQL 14 أو أحدث.

```bash
npm run reset && npm start
```

ثم افتح <http://localhost:3000>

| الأمر | ماذا يفعل |
|---|---|
| `npm start` | تشغيل الخادم على المنفذ ٣٠٠٠ |
| `npm run dev` | تشغيل مع إعادة التحميل التلقائي |
| `npm run seed` | بيانات أولية (إن كانت القاعدة فارغة) |
| `npm run reset` | مسح كل شيء وإعادة البناء |
| `npm test` | ٣٣٠ فحصاً على الخادم يعمل |
| `npm run readiness` | تدقيق جاهزية الرفع |
| `npm run check:wa` | فحص ربط واتساب (قراءة فقط) |
| `npm run backup` | نسخة احتياطية فورية |
| `npm run backup:list` | عرض النسخ المتاحة |
| `npm run restore -- --latest` | استعادة أحدث نسخة |

### حسابات التجربة

| الرابط | رقم التاجر | الباقة |
|---|---|---|
| [/yazan](http://localhost:3000/yazan) | `777000000` | بلس · موثّق · ٩ منتجات |
| [/nura-boutique](http://localhost:3000/nura-boutique) | `733445566` | مجانية · ٣ منتجات |

تسجيل الدخول من [`/login`](http://localhost:3000/login) برقم الجوال.
في وضع التطوير **يظهر رمز التحقق في الصفحة نفسها** وفي سجل الخادم.
لتفعيل الإرسال الحقيقي انظر [`SETUP-OTP.md`](SETUP-OTP.md)، ولربط واتساب
تحديداً [`SETUP-META.md`](SETUP-META.md) — وافحص الربط بـ `npm run check:wa`.

لوحة الإدارة: [`/admin`](http://localhost:3000/admin) — كلمة المرور `rvios-admin`
(غيّرها بمتغيّر البيئة `RVIOS_ADMIN_PASS`).

### روابط المتاجر بالإنجليزية

الرابط لاتيني حصراً (`/yazan` لا `/يزن`). السبب عملي: الرابط العربي يتحوّل
عند النسخ إلى ترميز مثل `%D8%B3%D8%A7%D8%B1%D8%A9` فيبدو مشوّهاً في واتساب
والبطاقات والإعلانات. المنصة تقترح رابطاً لاتينياً من الاسم العربي بالحرفنة
(«متجر ذو يزن للعطور» ← `dhu-yzn-atur`)، ويعدّله التاجر كما يشاء.

## القرارات التي تستحق الانتباه

### العزل مفروض بنيوياً لا بالانضباط (§٥.١)

الوثيقة تحذّر: «نسيان فلتر واحد يعني تسريب بيانات تاجر لتاجر آخر».
‏PostgreSQL يحلّ هذا بـRow Level Security، لكنها تُطبَّق على مستوى الدور
لا الطلب — والمنصة تتصل بدور واحد. لذلك فُرض المكافئ في الكود، وهو
أيضاً ما يجعل العزل قابلاً للاختبار بلا امتيازات قاعدة:

```js
const s = scope(store.id);          // البوابة الوحيدة
s.all('products', { live: 1 });     // store_id يُحقن دائماً
s.insert('orders', { ... });        // ويتجاهل أي store_id قادم من المُدخل
s.raw('SELECT … WHERE store_id = ?', [id]);  // يرفض أي SQL بلا store_id
```

لا يمكن الحصول على مقبض استعلام لجدول تابع دون `store_id`.
`verifyIsolation()` يفحص عند الإقلاع أن كل جدول تابع يملك العمود فعلاً.

> **عند الانتقال إلى PostgreSQL:** استخدم RLS الحقيقية بدل هذه الطبقة —
> فهي مكافئ عملي، لا بديل عن ضمانة قاعدة البيانات نفسها.

### الطلب يُسجَّل قبل واتساب (§٤.١)

هذه النقطة بالذات هي سبب رفض §٤.٢ لبديل «رابط واتساب مباشر».
`POST /api/shop/{slug}/orders` يكتب الطلب برقم مرجعي **ثم** يعيد رابط واتساب.
الأسعار تُقرأ من قاعدة البيانات لا من المتصفح، فلا يمكن التلاعب بها.

واتساب مجرد ناقل للتأكيد: طبقة الطلبات مستقلة عنه تماماً (§٨ خطر ٥)،
ويمكن استبداله بالدفع الإلكتروني دون لمس منطق الطلب.

### المتاجر المتعددة: خانات مملوكة لا حق مشتقّ

باقة برو **تفتح** شراء متاجر إضافية ولا تهدي متجراً. كل خانة تُشترى بفاتورة
`extra_store` وتُسجَّل في `merchants.store_slots`.

الخانة مملوكة للحساب لا مشتقّة من الباقة لحظياً — ولهذا سبب: لو اشتُقّت، لفقد
التاجر متجره الثاني في اللحظة التي ينتهي فيها اشتراكه، وهذا يخالف §٥.٥
«إخفاء لا حذف». ورفض إيصال الخانة يسحبها **ولا ينزل تحت عدد المتاجر القائمة**.

المتجر النشط يُحلّ بثلاث درجات في [`requireStore`](src/auth.js): ترويسة `X-Store`
(فتبويبان على متجرين يعملان معاً) ← المثبَّت في الجلسة ← الأقدم. المسارات الـ٢١
تحت `/api/me/` لم تتغيّر، و`scope()` تعزل متجراً عن متجر ولو كانا لنفس التاجر.

> متجر مطلوب لا يملكه التاجر يسقط بصمت إلى الافتراضي: لا نكشف وجوده، ولا نسمح بالوصول.

### المخزون يُحجز وقت الطلب لا وقت التأكيد

لو انتظرنا تأكيد التاجر، لأمكن لعميلين أن يطلبا آخر قطعة وينجح كلاهما —
وهي حادثة تُفقد الثقة بسرعة في سوق مترابط اجتماعياً (§٦.٢).
الحجز يجري داخل معاملة `BEGIN IMMEDIATE` تمنع السباق، والإلغاء يعيد الكمية.

### إشعار التاجر بالطلب

§٣.٣ تصف سرعة رد التاجر بأنها عنق الزجاجة الحقيقي — والطلب الذي لا يعلم به
التاجر لا قيمة له. عند تفعيل واتساب Cloud API يصل التاجر إشعار تلقائي بكل طلب.
الإشعار لا يُفشل الطلب أبداً إن تعذّر إرساله.

### HTML مولّد من الخادم (§٣.١)

السبب الأول ليس محركات البحث بل **واتساب**: هو قناة المشاركة الأساسية، ولا
ينفّذ JavaScript. رابط بلا وسوم Open Graph يظهر كنص أعرج بلا صورة ولا اسم —
وهذا يُفقد الرابط نصف قيمته وهو جوهر المنتج. [`src/render.js`](src/render.js)
يحقن العنوان والوصف والصورة وبيانات Schema.org ومحتوى المنتجات، ثم تعيد
الواجهة بناء الشبكة تفاعلياً.

### لون واحد يصبغ المتجر كله (§٣.٦)

التاجر يختار لوناً، ويُشتق منه في
[`public/assets/js/theme-core.js`](public/assets/js/theme-core.js) نحو عشرين
متغيّر CSS: الأسطح والحدود والحبر والوهج والظلال ولون التباين. الحساب يجري في
فضاء **OKLab** لا HSL — تفتيح الأحمر في HSL يعطي وردياً باهتاً وتغميق الأصفر
يعطي طيناً، بينما OKLab يحفظ الإحساس البصري بالإضاءة فتخرج التدرّجات نظيفة لأي
لون مهما كان.

قراران يستحقان الانتباه:

- `--on-shop` (النص فوق التعبئة) يُختار بحساب تباين WCAG لا بافتراض «الأبيض
  دائماً» — متجر بلون أصفر يحصل على نص داكن تلقائياً.
- `--shop-text` (اللون حين يكون نصاً فوق الورق) يُغمَّق أو يُفتَّح خطوةً خطوة
  حتى يبلغ ٤٫٥:١. بدونه تصبح أسعار متجر أصفر غير مقروءة (١٫٧:١).

الملف **نقي** بلا DOM، فيستورده [`src/render.js`](src/render.js) ويحقن اللوحة
في `<style>` قبل تحميل JS — فلا تومض الصفحة بألوان المنصة على إنترنت بطيء.

### الباقة تشتري درجة تصميم لا عدداً أكبر (§٢.١)

`data-tier` على `<html>` يفتح ثلاث درجات في
[`store-tiers.css`](public/assets/css/store-tiers.css):

| الباقة | الدرجة | ما تضيفه |
|---|---|---|
| مجانية | **نقي** | واجهة صافية بلونه كاملاً، بلا زخرفة |
| بلس | **دافئ** | هيرو متدرّج، شريط ثقة وتصنيفات، بطاقات ترتفع، ظهور تدريجي |
| برو | **فاخر** | وهج محيط، هيدر زجاجي، عنوان متدرّج، ضوء يتبع المؤشر، ٣ سكِنات |

القيد الأخلاقي المقابل (`NEVER_GATED`): الطبقة النقية ليست مُشوَّهة عمداً.
الفرق **إضافة** لا انتقاص، ولا نُبطئ المجانية ولا نحجب عنها وظيفة.

السكِن المحفوظ لا يُمسح عند الهبوط من برو (§٥.٥ إخفاء لا حذف): `effectiveTheme`
يعيد «التوقيع» للعرض، ويسترجع التاجر سكِنه لحظة الترقية.

### صورتان بدورين مختلفين

`banner` يزيّن أعلى الصفحة، و`showcase` (صورة العرض) تعيش في قسم «قصة المتجر»
مع نبذة التاجر ومدينته وأوقاته. صورة واحدة تُقصّ مرتين لا تصلح للدورين: الغلاف
عريض خلف عنوان، والعرض مربّع تقريباً بجوار نص.

### البحث والترقيم في الخادم (§٥.٣)

كتالوج كامل دفعة واحدة يعني ٧٩ ك.ب لمئة منتج على إنترنت بطيء. الصفحة تجلب
١٢ منتجاً، والبحث والفلترة والترتيب كلها في الخادم — وكل جملة تمرّ عبر
`scope.raw` الذي يرفض SQL بلا `store_id`.

### حدود الباقات تُفرض في الخادم (§٢.٢)

الحد المجاني (١٠ منتجات) مفروض في `POST /api/me/products`، لا في الواجهة فقط.
التصنيفات الفرعية كذلك — ترفض الباقة المجانية بـ `PLAN_LIMIT`.

### الصور ملفات لا `data URI` (§٥.٣)

«الصور هي أكبر بند تكلفة تشغيلية». تُضغط في المتصفح، ثم تُحفظ على القرص
في `uploads/stores/{id}/{kind}/{hash}.jpg` — نفس التنظيم الذي ستأخذه على S3،
فيصبح الانتقال تغيير `uploads.js` وحده. الاسم من محتوى الصورة، فالرفع
المكرّر لا ينتج ملفين.

### الأسعار المدفوعة تظهر «—»

§١١ تُدرج السعر النقدي ضمن **القرارات المعلّقة**. `price: null` في
[`src/plans.js`](src/plans.js) يعني «لم يُحسم»، وكل الواجهات تعرض `—`
بدل رقم مخترع يصعب التراجع عنه بعد إعلانه.

### الأرقام: عربية-هندية في الواجهة، لاتينية في رسالة واتساب

الواجهة كلها `ar-EG` اتساقاً مع §٧.١. رسالة واتساب وحدها بالأرقام اللاتينية
عن قصد ([`src/orders.js`](src/orders.js)): التاجر ينسخها ويحسب عليها ويعيد
إرسالها عبر تطبيقات مختلفة، واللاتينية أسلم في ذلك. الاتساق البصري مكانه
الواجهة، لا رسالة تشغيلية.

| البند | الحالة |

## ملاحظات نشر

- شغّل خلف وكيل عكسي (nginx/Caddy) مع HTTPS.
  الكوكي يأخذ علم `Secure` تلقائياً حين `NODE_ENV=production`.
- اضبط `NODE_ENV=production` — يُخفي رمز التحقق من الردود.
- اضبط `RVIOS_ADMIN_PASS` بقيمة قوية.
- فعّل مزوّد رموز التحقق — انظر [`SETUP-OTP.md`](SETUP-OTP.md) و[`SETUP-META.md`](SETUP-META.md).
- الأسرار في `.env` (مستثنى من Git). انسخ [`.env.example`](.env.example) وابدأ منه.
  **لا تضع مفتاحاً في الكود** — مفتاح واتساب مكشوف يعني استنزاف رصيد رسائلك.
- وجّه `‎/api/webhooks/whatsapp‎` عبر HTTPS لتصلك تقارير تسليم الرسائل.
- مرّر `X-Forwarded-Proto` و`X-Forwarded-Host` من الوكيل ليبني
  `render.js` روابط Open Graph المطلقة بشكل صحيح.
- **لا تُفعّل ضغط الوكيل** — التطبيق يضغط بنفسه (brotli ثم gzip،
  توفير ٧٣–٧٥٪). الضغط مرتين يستهلك المعالج بلا فائدة.
- `DATA_DIR` يحدّد مكان القاعدة والصور. في الحاوية اجعله حجماً
  منفصلاً وإلا مُحيت البيانات مع أول تحديث.
- المنفذ من `PORT` (افتراضياً ٣٠٠٠)، والعنوان من `HOST`.

### التشغيل

- **`/health`** يستعلم القاعدة فعلاً — لا يكتفي بأن المنفذ مفتوح.
  وجّه الوكيل إليه، ولا تُسجّله في السجل.
- **إيقاف رشيد** عند `SIGTERM`: يتوقّف القبول، تنتهي الطلبات
  الجارية، تُؤخذ نسخة أخيرة، ثم تُغلق القاعدة.
- **معرّف طلب** في ترويسة `X-Request-Id` وفي كل سطر سجل. عند
  الشكوى يقتبسه التاجر فتجد الطلب فوراً.
- **السجل JSON** تلقائياً في الإنتاج (`LOG_JSON`).

### تطبيق ويب تقدّمي (PWA)

اللوحة قابلة للتثبيت على الشاشة الرئيسية، وعامل الخدمة يخزّن
القشرة فتصبح الزيارة الثانية فورية على شبكة بطيئة.

**قاعدة حاكمة: لا يُخزَّن أي رد من `/api`.** تاجر يرى «٣ طلبات
منتظرة» وهي في الحقيقة ١١ سيخسر عملاء، وسيلوم المنصة لا الشبكة.
البيانات القديمة أسوأ من غيابها.

- الصور وأصول البصمات: من الذاكرة أولاً (محتواها ثابت).
- الصفحات: الشبكة أولاً، والذاكرة شبكة أمان — صفحة المتجر تتغيّر
  كلما عدّل التاجر منتجاته، وعرض سعر قديم لعميل ضرر لا فائدة.
- عند انقطاع الشبكة تظهر [`offline.html`](public/offline.html) وتوضّح
  أن العطل في الاتصال لا في المتجر.
- `VERSION` في [`public/sw.js`](public/sw.js) **يجب أن يتغيّر مع كل نشر**
  وإلا بقي المتصفح على أصول قديمة.

> التسجيل الفعلي لعامل الخدمة يحتاج متصفحاً حقيقياً — متصفحات
> الأتمتة تُعطّله. تحقّق منه في Chrome:
> `DevTools ← Application ← Service Workers`.

### النسخ الاحتياطي

يعمل تلقائياً في الإنتاج كل ٦ ساعات (`BACKUP_INTERVAL_HOURS`)،
ويحتفظ بآخر ١٤ نسخة (`BACKUP_KEEP`).

- القاعدة تُنسخ بـ`pg_dump` — لقطة متّسقة داخل معاملة واحدة.
  يحتاج `postgresql-client` على المضيف؛ بدونه تُنسخ الصور وحدها
  ويُعلَن التخطّي في السجل بدل أن يمرّ صامتاً.
- كل نسخة **تُفتح ويُفحص تكاملها فور إنشائها**؛ التالفة تُحذف ولا تُحفظ.
- الصور تُنسخ تزايدياً (أسماؤها بصمات محتوى) فالنسخة اليومية شبه مجانية.
- الاستعادة تحفظ القاعدة الحالية في `.before-restore` قبل الدهس.

```bash
npm run backup:list
```

### ترويسات الأمان المطبَّقة

`Content-Security-Policy` (بلا `unsafe-inline` للسكربتات) ·
`X-Content-Type-Options` · `X-Frame-Options` · `Referrer-Policy` ·
`Permissions-Policy`.

> بسبب CSP الصارم **لا تضع سكربتات مضمّنة في HTML** — ضعها في
> `public/assets/js/` كملف خارجي، وإلا حجبها المتصفح.

## النماذج الأصلية

ملفات `rvios-*.html` في الجذر هي النماذج الأولية الثابتة التي سبقت هذا التنفيذ.
احتُفظ بها للرجوع البصري؛ الصور التي كانت مضمّنة فيها استُخرجت إلى
`public/assets/img/`. لا يعتمد عليها التطبيق العامل.
